**Fix for the weak spot:** the 3 per-node IPs are the 3 layers of a node, bottom-up — **hardware (IPMI) → hypervisor (AHV) → Controller VM (CVM)**. IPMI is out-of-band management: if the node is down, it is the only IP still answering.

**Subnet drill (prefix → decimal):** `/30` → block size **4**, **2** usable hosts, `255.255.255.252` ✅ — the standard size for a point-to-point link (one IP per end).

**Objective 1.2, part 1:** each cluster ships with its own **Prism Element**; **Prism Central** is deployed from it as a VM inside a cluster, has its own IP and only sees the clusters registered to it. Check: 3 clusters, no Prism Central → **3** Prism Element instances ✅.

**Teach-back (fixed):** *I can access the server through the IPMI. From there, I can control it remotely: power it on and off, and reboot it.* (fixed *serve* → *server*, *controll* → *control*, *remotaly* → *remotely*, and added the object: *control **it***.)

**Why it matters for DevOps:** out-of-band management is the last way in when the OS and the automation are down — knowing which address still answers is the first step of any incident runbook.
