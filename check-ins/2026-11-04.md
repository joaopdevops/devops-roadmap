**Fix for the weak spot:** the 3 per-node IPs are the 3 layers of a node, bottom-up — **hardware (IPMI) → hypervisor (AHV) → Controller VM (CVM)**. IPMI is out-of-band management: if the node is down, it is the only IP still answering. Evening slip: CVM listed before AHV — the name settles it: the CVM is a **VM**, so it runs on top of AHV.

**Subnet drill (prefix → decimal):** `/30` → block size **4**, **2** usable hosts, `255.255.255.252` ✅ — the standard size for a point-to-point link (one IP per end).

**Objective 1.2 — Prism Element vs Prism Central**
- Each cluster ships with its own **Prism Element**, which only sees that cluster. **Prism Central** manages many clusters from one place: it runs as a **VM inside one of the clusters**, has **its own IP** (not the cluster Virtual IP) and only sees the clusters **registered** to it. If its host cluster goes down, Prism Central goes down too, but the other clusters keep running and stay reachable through their own Prism Element.
- Both web consoles use port **9440**. Cross-cluster work, such as consolidated **reports**, belongs to Prism Central.
- Setting it up: an empty Prism Central means no cluster is registered yet, and registration starts from each cluster's Prism Element. Then identity and access: **AD/LDAP** answers *who you are* (the company login) and **RBAC** answers *what you can do* (roles, e.g. read-only → built-in role *Prism Viewer*). Prism Central also needs its own NTP, DNS and SMTP settings.
- Recall check (fact / relation / application): **3/3** ✅

**Teach-backs (fixed):**
- IPMI: *I can access the server through the IPMI. From there, I can control it remotely: power it on and off, and reboot it.* (fixed *serve* → *server*, *controll* → *control*, *remotaly* → *remotely*, and added the object: *control **it***.)
- Prism Central: *Each cluster has its own Prism Element, but it only sees that cluster. Prism Central helps us manage all the clusters from one place, and some features only exist there, like reports.* (fixed *it help* → *it **helps*** — third person singular takes **-s** — and used the full product name instead of "PC", which a listener hears as "computer".)

**Why it matters for DevOps:** out-of-band management is the last way in when the OS and the automation are down, and access should follow roles, not people — the same idea as IAM roles in the cloud: onboarding or offboarding someone becomes one change instead of dozens.
