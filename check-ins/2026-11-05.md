## 🇬🇧 English

**What I built:** a browser-based network-operations simulator ("Plantão de Rede") on a fictional spine-leaf network (2 spines, 4 leafs, 2 border routers, documentation IP ranges only). It has two modes:

| Mode | Missions | What the learner does |
|---|---|---|
| **Investigate** (read-only) | 12 | Alert → triage → `show` commands on Juniper (Junos), Arista (EOS) and Nokia (SR OS) → diagnosis → ticket in English |
| **Configure** (new today) | 5 | Change window → pre-check → `set` / `configure session` / MD-CLI → review the diff → commit → post-check on the network itself |

**Configure missions, and what each one teaches**

| # | Vendor | Task | Concept |
|---|---|---|---|
| C1 | Juniper | Customer VLAN 330 + access port, mapped to a VXLAN VNI | candidate vs. running config, `show \| compare`, `commit check` |
| C2 | Arista | 2×10G LAG with LACP in a configuration session | `channel-group` modes (active / passive / on), `write memory` |
| C3 | Juniper | Gateway redundancy on two leafs (VRRP group, VIP, priority) | same group on both sides, otherwise two masters |
| C4 | Juniper | Overnight change (MTU 1514) broke an IS-IS adjacency | `show system commit`, `compare rollback 1`, `commit confirmed` |
| C5 | Nokia | Re-enable an upstream BGP session after provider maintenance | MD-CLI private candidate, `admin-state`, `Bad Peer AS` |

**How it grades:** each mission checks the **final state of the simulated network**, not the commands typed. The engine applies a commit to the device model (ports, LAG/LACP bundling, VLANs and learned MACs, VRRP election across both peers, IS-IS adjacency from MTU, BGP session state), and `commit confirmed` rolls back automatically in real time if it is not confirmed.

**Testing:** all five missions solved end-to-end through the terminal UI; a regression run of 2,123 commands over the 12 older missions produced zero exceptions.

**Why it matters for DevOps:** the same loop runs every change in infrastructure as code — review the diff, validate before applying, keep a rollback path, and verify the *outcome*, not the command. `commit confirmed` is the network version of a deployment with an automatic rollback.
