## 🧭 CCNA 200-301 v2.0 — what changes

Cisco published the exam topics for **CCNA 200-301 v2.0**. It goes live on **3 Feb 2027** (v1.1 ends on 2 Feb). Same exam code, same 120 minutes, same certification. My exam window is **late April to mid May 2027**, so I'm preparing for v2.0.

| Weight | Domain |
|---|---|
| 25% | Network Infrastructure and Connectivity |
| 25% | Switching and Network Access |
| 20% | IP Routing |
| 20% | Network Services and Security |
| 10% | AI, and Network Operations and Management |

- **The verbs changed.** Most topics now say *troubleshoot* or *diagnose*, not *describe*. The exam description says candidates may have to **evaluate recommendations from agentic AI and network assistants**.
- **New for me:** client connectivity on Windows/macOS/Linux, CDP/LLDP to validate documentation, STP guards, OSPFv3, TACACS+/RADIUS, SFTP/SCP, DNS record types, storm control, RA guard, prompting and agentic AI, infrastructure as code.
- **Less weight now:** the OSI model in depth (it stays as troubleshooting vocabulary), TCP vs UDP as a standalone topic, QoS, NTP, REST/JSON.

## 🗺️ How I rebuilt the plan

- Mapped all **29 official topics** to the material I already have (NetAcad ITN/SRWE modules and the Official Cert Guide chapters) and flagged the gaps that need new material.
- Order: troubleshooting fundamentals → switching → routing + IPv6 → services and security → operations and AI → full review with weekly practice exams. A checkpoint on 31 Jan decides whether the exam window holds.
- **Booking rule:** two full practice exams in a row at ≥ 85%.
- **New lesson rule:** every lesson ends with one fault to find, because the exam is now about diagnosis.

## 📚 Lesson: the OSI model as working vocabulary

- 7 layers, but day-to-day ops lives in layers 1–4: a "layer 1 issue" is a cable, fiber or optic; layer 2 is the switch and MAC addresses; layer 3 is IP and routing.
- Troubleshoot **bottom-up**: there's no point changing configuration while the cable is loose.

## Why it matters

Planning against the official blueprint instead of a course outline means I don't spend weeks on topics that are no longer tested, and I start the new troubleshooting-heavy topics early. It's the same habit as reading the change log before an upgrade.
